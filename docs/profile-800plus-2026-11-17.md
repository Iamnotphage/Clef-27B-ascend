# 800+ token 专项分析（2026-11-17）

## 1. 结论

- **800+ token 是设备 compute-bound**。967 token profile（cache-only、NZ 前，`docs/profile-final-2026-11-17.md`）：compute union **144.6 ms** / kernel window **174.3 ms（83%）**；通信非重叠 17.2 ms（9.9%），非 kernel 12.5 ms（7.2%）。
- 主要计算项（每请求，967 token）：

| 设备 op | ms | 占 compute |
| --- | ---: | ---: |
| MLP gate/up（`967,5120 × 17408,5120`） | 42.65 | 29.5% |
| GDN `ChunkGatedDeltaRuleFwd` | 23.31 | 16.1% |
| MLP down（`967,8704 × 5120,8704`） | 21.23 | 14.7% |
| MatMul `5120→8192` | 14.86 | 10.3% |
| MatMul `5120→3072` | 8.06 | 5.6% |
| AddRmsNorm | 5.96 | 4.1% |
| `ClefGdnQkvNorm` | 4.66 | 3.2% |
| MatMul `5120→7168` | 4.46 | 3.1% |
| CausalConv1d | 3.79 | 2.6% |
| SwiGlu | 2.39 | 1.6% |
| Fused attention | 1.67 | 1.2% |

- MLP 合计（gate/up + down + SwiGlu）约 **66.3 ms（45.8%）**，GDN 主核 16.1%，其他 matmul 约 **28 ms（19%）**。

- chunk 32 不支持（aclnn 161002）；chunk 128 速度更快但数值不可用，**GDN 主核无参数杠杆**。

### 2.2 MLP 形状与 M padding（NZ，cold）

| T | gate/up ms | TFLOPS | padded M | padded TFLOPS | padded / raw |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,084 | 0.689 | 280.5 | 1,152 | 298.1 | ~1.000 |
| 1,200 | 0.728 | 293.9 | 1,280 | 313.5 | ~1.000 |
| 1,258 | 0.709 | 316.4 | 1,280 | 322.0 | ~1.000 |
| 1,595 | 0.952 | 298.6 | 1,664 | 311.6 | ~1.000 |

- 1,200 token 的 MLP gate/up 已约 **294 TFLOPS**，接近 300–320 的 BF16 Cube 平台；M padding 的 tiling 提升正好被多出的 6–7% 计算抵消，**净收益为 0**。
- 纯 MLP tiling 的理论空间约 2–8% MLP，折合端到端约 **2–3%**，需要自定义 tiling。

## 3. 800+ 专项尝试

### 3.1 All-linear BF16 NZ（已测试，不采用）

- 在 `Qwen3NextDecoderLayer.forward` 首次前向时把每层所有 2D BF16 权重转 FRACTAL_NZ（实测每层转换 **5 个**：attention qkv/o、GDN in/out、MLP gate/up/down），`CLEF_LAYER_BF16_NZ=1`。
- 全量 S1：**mean 123.85 / p50 114.84 / p95 166.61 / p99 205.30 ms、8.07 dec/s**；MLP-only NZ 为 121.71 / 113.66 / 166.00 / 204.32、8.213。
- 结论：**无收益、略差**（p95 +0.61 ms、mean +1.8%），不采用；已恢复 v4（SHA `a4de9b4e…`），三份安装器 `--check` ready。
- 解释：profile 中“其他 matmul”约 28 ms，但其形状（5120→8192/3072/7168）与 MLP 不同，NZ 的收益不足以抵消格式/首用开销；MLP-only 仍是最优组合。

### 3.2 剩余高成本方向（未执行）

- **QKV norm v3**（tile 级归约）：`ClefGdnQkvNorm` 在 967 为 4.66 ms（3.2%），v3 预计端到端 1–1.5%。
- **conv + QKV norm 融合**：CausalConv1d 3.79 ms + QKV norm 4.66 ms，融合可省一次中间写回，预计 1–2 ms。
- **MLP 自定义 tiling**：2–3% 端到端，但需要 Ascend C matmul/tiling 工作量。
- **通信重叠**：非重叠 17.2 ms，但 Dense SP、MC2、GEMM+AllReduce 分块均已在 2026-11-15/16 实测失败或退化，优先级最低。
