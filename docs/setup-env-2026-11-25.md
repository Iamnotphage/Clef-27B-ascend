## 2. `vllm_ascend_C` 编译失败：真实错误与根因

复现命令（`.build/src/vllm-ascend` 下，`-v` 日志落盘 `/tmp/va-build-diag.log`）：

```
cmake --build . -j=8 --target=vllm_ascend_C
```

真实错误：

```
TooFewObj: There is no obj file in this directory:
  /tmp/tmp96rwzof7.build-temp/vllm_ascend_kernels_host_dir
gmake[3]: *** [.../lib/libvllm_ascend_kernels.so] Error 1
```

CANN 的 `legacy_modules/util/recompile_binary.py::get_add_obj` 使用：

```python
objs = glob.glob(f"{add_dir}/**/*.o", recursive=True)
```

CMake 安装 `OBJECT` 库时会把对象文件按**源码绝对路径**放到安装前缀下，实测对象在：

```
.../vllm_ascend_kernels_host_dir/objects-Release/host_bisheng_obj/
  workspace/final-test/Clef-27B-ascend/.build/src/vllm-ascend/csrc/kernels/*.o
```

路径中含 `.build`。Python 3.11+ 的 `glob` 默认 `include_hidden=False`，`**`
**不会进入隐藏目录**，因此：

```
glob('.../vllm_ascend_kernels_host_dir/**/*.o', recursive=True)            -> []
glob(..., recursive=True, include_hidden=True)                              -> 4 个 .o
```

即：旧脚本把源码树放在 `<repo>/.build/src`，恰好触发 CANN 构建脚本的隐藏目录缺陷。
原机器 `/workspace/yangchen/work/src` 不含隐藏路径，所以从未暴露。

**修复**：源码树改到非隐藏目录 `<repo>/build/src`（`/build/` 已加入 `.gitignore`），
`.build/` 仍用于日志、材料、缓存；脚本在启动时自动把旧的 `.build/src` `mv` 到
`build/src`。用非隐藏路径手工配置后实测：

```
[100%] Linking CXX shared module vllm_ascend_C.cpython-312-aarch64-linux-gnu.so
[100%] Built target vllm_ascend_C
```

`COMPILE_CUSTOM_KERNELS=1` 保持开启，未关闭任何 Ascend C 算子。

**同一根因的第二个命中点**：`mfcli kernel install --soc-version A3`（MemFabric
AccOffload）把 kernel 源码放在 `.venv/lib/python3.12/site-packages/memfabric_hybrid`
下，对象安装路径同样含隐藏的 `.venv`，失败信息为
`TooFewObj: ... /tmp/acc_offload_extend_*/kernel_build/mf_accoffload_kernel_host_dir`。
修复：新增 `scripts/compat/glob_hidden/sitecustomize.py`，仅在 mfcli 进程树中通过
`PYTHONPATH` 注入，把 `glob.glob` 的默认 `include_hidden` 设为 `True`；不修改
CANN 系统文件，也不影响其他进程。实测该步 `Install done` 并生成
`libmf_hybm_accoffload.so`。

## 3. 脚本改造清单

### 3.1 `scripts/activate_env.sh`

- `CLEF_WORKSPACE` 默认改为 `<repo>/.build`；`CLEF_LOG_DIR` = `<repo>/.build/logs`，
  `XDG_CACHE_HOME` = `<repo>/.build/cache`，`MODEL_DIR` 默认 `<repo>/.build/models/Clef-27B`。
  不再在 `/workspace/yangchen` 下创建/依赖任何目录；需要旧布局时显式
  `export CLEF_WORKSPACE=/workspace/yangchen`。
- CANN/ATB 自动探测 `/usr/local/Ascend/cann/set_env.sh`、
  `/usr/local/Ascend/ascend-toolkit/set_env.sh`、`/usr/local/Ascend/cann-*/set_env.sh`
  与 `/usr/local/Ascend/nnal/atb/{,latest/}set_env.sh`。

### 3.2 `scripts/setup_env.sh`

- **源码树非隐藏**：`CLEF_SRC_ROOT` 默认 `<repo>/build`，自动迁移旧 `.build/src`。
- **archive 默认优先**：实测本容器到 GitHub 的 git 智能协议经常被代理限速到
  ~8 KB/s 或出现 HTTP2 framing 错误，而 codeload archive 可达 0.3–10 MB/s。
  默认先下载固定提交 GitHub archive（`https://github.com/<repo>/archive/<sha>.tar.gz`，
  代理轮询、curl 续传重试），脚本内置 SHA-256 校验：
  vLLM `e933f065…`、vLLM-Ascend `9b59a634…`、EvalScope `61c596f4…`。
  vLLM-Ascend 的两个子模块从其 `.gitmodules` 指向的 gitcode 固定提交浅拉取：
  catlass `41bf90da…`、googletest `f8d7d77c…`。archive 模式用
  `.clef-source-commit` marker 校验固定提交，并用
  `SETUPTOOLS_SCM_PRETEND_VERSION` 固定分发版本
  （vLLM `0.33.0rc1.dev370+g24420b7a3`、vLLM-Ascend `0.1.dev1+g89eb8a5e7`）。
- **git 浅拉取回退**：archive 失败后才尝试
  `git init + fetch --depth 1 origin <sha> + checkout --detach FETCH_HEAD`；
  代理按 `gh-proxy.com → ghproxy.net → 直连` 轮询，每个源先 `git ls-remote` 15s
  探测、fetch 60s 硬超时；仍失败则完整 clone（1800s）。
  `CLEF_FORCE_GIT=1` 改为 git 优先；`CLEF_FORCE_TARBALL=1` 只用 archive、不回退 git。
- **浅拉取成功路径**：冷构建实测暴露一个控制流缺陷——`fetch --depth 1` 成功
  （`cloned=1`）后缺少 verify/return，会落空到最终 `die`。已补上
  `if cloned==1: submodule update + verify_source + return`。
- **完整性校验**：git 模式 HEAD 必须等于固定 commit，递归子模块
  `submodule status --recursive` 不得出现 `-`/`+`；archive 模式校验 tarball
  SHA-256、父/子模块 marker 与固定提交；不完整/半途目录自动删除重拉。
- **uv 加速**：从华为云 PyPI 安装 `uv==0.13.10`（失败自动回退 pip）；所有纯 wheel
  安装优先 `uv pip install --python .venv/bin/python`，使用
  `--index-strategy unsafe-best-match`（跨华为 PyPI + 华为 Ascend 索引匹配
  `memcache-hybrid` 等 Ascend 独有包），失败自动回退 `python -m pip install`。
- **安装顺序修复**：先 `requirements.txt`（含 `triton==3.6.0`），再
  `--force-reinstall --no-deps` 覆盖 `triton-ascend==3.6.0.post2`；验收断言
  `'ascend' in triton.backends.backends`、打印 `triton.__file__`。
- **requirements 安装**：`--no-deps`（199 包完整冻结锁），额外
  `--extra-index-url` 华为 Ascend PyPI，`--prefer-binary`；完整性由 `pip check` 验收。
- **flash_attn_npu 默认跳过**：服务路径不引用它（见第 6 节实测），默认不编译；
  `--with-flash-attn` 显式开启。`verify_npu_environment.py --require-extensions`
  仍记录它的存在/版本，但不再作为失败条件；`--require-flash-attn` 可强制要求。
- **计时 Python 修正**：`setup-timing.json` 现在用 `"$venv/bin/python"` 写出，
  `python` 字段为 3.12.16（不再记录构建前的系统 Python 3.10.12）。
- **评测依赖**：`scripts/requirements/evalscope-api.txt` 严格带
  `--constraint runtime-constraints.txt --constraint requirements.txt`；EvalScope
  以 `pip install --no-deps -e build/src/evalscope` 安装固定提交
  `3d39bab09c1d63095490a8b0f4a6dcbcc5ea843e`。
- **依赖冲突修复**：`datasets==3.6.0` 要求 `dill<0.3.9`、`fsspec<=2025.3.0`，
  已把 `dill` 从 `0.4.1` 降到 `0.3.8`、`fsspec` 从 `2026.9.0` 降到 `2025.3.0`
  （`depyf`/`transformers`/`huggingface_hub` 无下界冲突），并写入
  `runtime-constraints.txt`。
- **MAX_JOBS**：读 cgroup v2 `cpu.max` 或 v1 `cpu.cfs_quota_us`、`memory.max` /
  `memory.limit_in_bytes`，取 `min(配额核数, 内存 GiB/4, 16)`；本容器为 16。
- **分阶段计时**：每个阶段写 `<repo>/.build/logs/setup-timing.json`（阶段名、秒数、
  状态、总耗时、MAX_JOBS、Python 版本），失败也会落盘。
- **参数**：`--pip-only`（只装全部 pip 层，含评测，不编译源码）、`--no-eval`、
  `--force`；完成标记升级为 `clef-env-v3`。
- **错误定位**：构建失败自动打印 `error:` / `fatal error` / `CMake Error` /
  `Killed` / `TooFewObj` / `undefined reference` 上下文。
- **MemFabric 兼容钩子**：`scripts/compat/glob_hidden/sitecustomize.py` 仅在
  `mfcli kernel install` 的进程树中启用 `glob(include_hidden=True)`，修复
  `.venv` 隐藏路径导致的 AccOffload kernel `TooFewObj`。
- **默认模型目录**：`inference.py` 的 `DEFAULT_MODEL_DIR` 从
  `/workspace/yangchen/models/Clef-27B` 改为 `<repo>/.build/models/Clef-27B`
  （`--model-dir` / `MODEL_DIR` 仍然优先）。
- **archive 模式的验收兼容**：`scripts/verify_npu_environment.py` 在源码树无
  `.git` 时读取 `.clef-source-commit`，避免 `git -C` 向上误读父仓库 HEAD；
  `inference.py` 的 `launch-manifest.json` 同样以 marker 记录
  `software.{vllm,vllm_ascend}.git_head`（`head_source=marker`）。
- **root 下的只读判定**：`inference.py::resolve_vllm_tree` 原来只用
  `os.access(..., os.W_OK)`，root 对 0444 仍返回可写，导致
  `test_joint_fused_entry` 的只读用例失败；改为同时检查 mode 位（`& 0o222`）
  与 `os.access`（覆盖只读挂载/ACL）。

`flash_attn_npu` 处理：华为 Ascend PyPI 稳定/夜间索引与华为云 PyPI 均**无**
`flash_attn_npu==0.5.0` 预编译 `cp312 aarch64` wheel（实测 `pip download
--only-binary=:all:` 报 `No matching distribution`），只能源码编译；保持默认编译，
未静默跳过。审计见第 6 节。

## 7. 复现命令

```bash
cd <repo>
unset VIRTUAL_ENV PYTHONPATH CLEF_VENV CLEF_MATERIALS CLEF_WORKSPACE CLEF_SRC_ROOT CLEF_BUILD
time bash scripts/setup_env.sh
source scripts/activate_env.sh
python -m pip check
bash start.sh --model-dir <MODEL_DIR> --output-dir <OUT_DIR>
```

只验证 pip 层：`bash scripts/setup_env.sh --pip-only`。
跳过评测：`bash scripts/setup_env.sh --no-eval`。
需要 flash_attn_npu：`bash scripts/setup_env.sh --with-flash-attn`。
默认 archive 优先；强制 git 优先：`CLEF_FORCE_GIT=1 bash scripts/setup_env.sh`；
只用 archive：`CLEF_FORCE_TARBALL=1 bash scripts/setup_env.sh`。
