# S1 warmup 对照（2026-11-17）

## 结论

- 之前的 S1 表格均为 `--warmup 0` 直接开始（`od-full` 报告 warmup 为空）。
- **warmup 只改善首请求冷启动和瞬时短请求离群**：首请求 677.9 → 120–129 ms；`od-2185/od-2186` 从 390.9/361.6 回到 102 ms；短预热的正式遍 max 从 677.9 降到 248.0 ms（与最长真实请求 ~247 ms 一致）。
- **800+ token 的长题不受 warmup 影响**：0–400 token 仍约 108–112 ms，801–1000 约 157 ms，1001–1200 约 186 ms，1201–1400 约 210 ms，1401–1600 约 237 ms；这是设备计算量，不是缓存/首用。
- p95 只从 166.00 降到 **165.19–165.43 ms**（−0.6～−0.8 ms），p99 约 −1 ms；mean/p50 的变化（full warmup 的 119.37/109.10）主要来自时钟/持续负载，且与跨运行漂移同量级。
- 不建议为 S1 加 **全量预热**（约 5 分钟启动成本，仍可能出现瞬时离群）；若主办方允许在测量前预热，**32 条、覆盖 200–1500 token 的短预热**（约 5 s）是最佳折中。
- 当前提交版本未改：服务启动后没有内置 warmup，702 行的评估客户端直接开始；是否加短预热取决于官方测量协议，避免后台预热与首批测量请求竞争。
