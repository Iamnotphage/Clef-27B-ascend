# S1 warmup 对照（2026-11-17）

## 结论

- 之前的 S1 表格均为 `--warmup 0` 直接开始（`od-full` 报告 warmup 为空）。
- **warmup 只改善首请求冷启动和瞬时短请求离群**：首请求 677.9 → 120–129 ms；`od-2185/od-2186` 从 390.9/361.6 回到 102 ms；短预热的正式遍 max 从 677.9 降到 248.0 ms（与最长真实请求 ~247 ms 一致）。
- **800+ token 的长题不受 warmup 影响**：0–400 token 仍约 108–112 ms，801–1000 约 157 ms，1001–1200 约 186 ms，1201–1400 约 210 ms，1401–1600 约 237 ms；这是设备计算量，不是缓存/首用。
- p95 只从 166.00 降到 **165.19–165.43 ms**（−0.6～−0.8 ms），p99 约 −1 ms；mean/p50 的变化（full warmup 的 119.37/109.10）主要来自时钟/持续负载，且与跨运行漂移同量级。
- 不建议为 S1 加 **全量预热**（约 5 分钟启动成本，仍可能出现瞬时离群）；若主办方允许在测量前预热，**32 条、覆盖 200–1500 token 的短预热**（约 5 s）是最佳折中。
- 当前提交版本未改：服务启动后没有内置 warmup，702 行的评估客户端直接开始；是否加短预热取决于官方测量协议，避免后台预热与首批测量请求竞争。

## 多轮平均（比赛允许 warmup、成绩多轮平均）

- 短预热：8 条代表样本（200–1500 token）×4 = 32 条，约 5.6 s；随后同一服务连续 3 轮全量 S1，取平均。
- 短预热后 3 轮：mean 122.94/120.25/119.84，p50 115.08/109.61/110.10，p95 166.60/165.51/165.74，吞吐 8.129/8.311/8.339。
- **3 轮平均：mean 121.01 / p50 111.60 / p95 165.95 / p99 204.04 / 8.26 dec/s**；无预热单轮为 121.71 / 113.66 / 166.00 / 204.32 / 8.213。
- 结论：短预热 + 3 轮平均的 **p95 与无预热持平（165.95 vs 166.00）**，mean −0.7 ms、p50 −2.1 ms、吞吐 +0.6%；首请求 677.9 ms 的冷启动被清掉，但第 2/3 轮仍偶发 500–647 ms 的瞬时离群（p99 不受影响）。
- **全量预热（2352 条）变体作废**：执行时 host CPU load 从 138 升到 187（32 核配额严重争用），该轮所有 token 桶均 +20–25 ms（0–400 token ~110→~135），服务停掉后负载仍上升；这是外部环境，不是预热效果。正常负载下的全量预热第二遍此前为 119.37/109.10/165.43/8.373，但启动多 5 分钟，p95 与短预热相同。
- 建议：比赛若有 warmup 阶段，用 **32 条短预热**（约 5 s）即可；不需要全量预热。多轮平均必须在 host 负载稳定时测，外部 CPU 争用会把 p50/mean/p95 整体抬高。
