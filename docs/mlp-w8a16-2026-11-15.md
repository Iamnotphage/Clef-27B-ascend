# MLP W8A16 候选与激活平滑评估（2026-11-15）

在 W8A8 候选（Capability −0.354）之后，评估两个方向：**W8A16（权重 INT8、激活 BF16）**能否以更小质量代价拿到同样收益；以及**激活平滑**能否把 W8A8 的误差压回可接受范围。

## 1. W8A16 候选

W8A16 与 W8A8 使用**完全相同的 checkpoint 张量**（INT8 weight + BF16 `weight_scale` + `weight_offset`），只是 `quant_model_description.json` 的 128 个 gate/up 条目从 `W8A8_DYNAMIC` 改为 `W8A16`；候选目录 `/workspace/yangchen/models/Clef-27B-mlp-gateup-w8a16` 硬链接复用权重。服务以 `--quantization ascend` 正常加载，modelslim 路径生效。

| 指标 | BF16 | W8A16 | 加速 |

W8A16 的局部加速远低于 W8A8 的 1.35–1.63×：权重字节减半，但 `npu_weight_quant_batchmatmul` 的 dequant/调度开销吃掉了大部分收益。

## 2. 激活平滑仿真（CPU，真实捕获输入）

对 gate/up 的输入按通道做 SmoothQuant 式缩放（`x/s`、`W*s`），再走当前 W8A8 动态量化。隐藏层 relative RMSE：

| 点 | W8A16 | W8A8 | W8A8+smooth(shared α=0.7) |
| --- | ---: | ---: | ---: |
| layer0 / od-0105 | 0.48% | 1.49% | 1.00% |
| layer31 / od-0105 r0 | 1.29% | 11.78% | 2.37% |
| layer31 / od-0105 r1 | 1.28% | 11.84% | 2.27% |
| layer63 / od-0105 | 0.31% | 1.12% | 0.68% |
| layer31 / erqa-0089 (662) | 1.26% | 11.04% | 2.38% |

平滑把最坏层误差从 11.8% 降到 2.4%（5×），同时保留 INT8 的 1.35× 局部速度；代价是需要逐层校准激活、把 `1/s` 折进 MLP 前的 RMSNorm、把 `s` 折进 gate/up 权重列，并重新转换 checkpoint。

## 3. 收益上限判断（关键）

- MLP 占设备 kernel 时间 **31.6%**（32.07/101.6 ms，307-token 模板）。
- 但端到端 S1 p95 约 **213 ms**，设备 kernel 合计约 **101.6 ms**，近一半在 kernel 之外（HTTP/CPU/排队/同步/通信等待）。
- 因此 MLP 局部 1.35×（省约 8 ms 设备）对应的端到端上限约 **4%**；实测 W8A8 全模型仅 **+0.28% 吞吐 / −0.94% P95**。W8A16 局部 1.057×（省约 1.8 ms）对应 <1%，与全量持平一致。
- 结论：**继续在 MLP 量化上抠收益的上限很低**，即使平滑把质量恢复到接近 BF16，端到端也只有约 1% 量级。

## 4. 结论与建议

1. **W8A16 不作为性能候选**：质量更好但局部仅 1.057×，全量无收益。
2. **激活平滑是 W8A8 质量问题的正解**（仿真 11.8%→2.4%），但端到端上限约 1%；是否投入取决于能否接受这一 ROI。
3. 更高 ROI 的方向：
   - **批处理**：seqs4 13.764 dec/s（2.4×），只受质量政策约束（用户正在评估 0.097 是否可接受）；
   - **TP2 allreduce 重叠**：20.4 ms/请求（20.1%），与 MLP 同量级；
   - **GDN 剩余布局**：q/k/v 转置 5.86 ms（6.6%），融合风险低于量化；
   - **非 kernel 的一半**：host/HTTP/排队/同步，需单独 profile。
