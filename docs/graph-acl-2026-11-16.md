# Graph / ACL graph 可行性测试（2026-11-16）

目标：验证 vLLM-Ascend 在 BIC S1 pooling 服务上能否启用 ACL graph，并测量它能否降低 64 层 eager dispatch。结论：**可以启动、冻结 8/8，但没有收益**；307 token 反而比 eager 慢约 5–6%，967 token（S1 P95）基本持平。不采用。

## 1. 配置

- 直接 vLLM 启动，**不加 `--enforce-eager`**；TP2/BF16/pooling/4096/seqs1/缓存关；
- BIC 环境：`CLEF_GDN_DECISION_PREFILL=1`、`NO_RECOMPUTE=1`、`BSND=1`、`SKIP_INITIAL_STATE=1`、`SKIP_CONV_STATE=1`；
- vLLM 日志：
  - `Pooling models do not support full cudagraphs. Overriding cudagraph_mode to PIECEWISE.`
  - `cudagraph_mode=PIECEWISE`、`cudagraph_capture_sizes=[1]`；
  - 每 rank `torch.compile` 约 **26.8 s**，`compile range (1,4096)`；
  - ACL graph 捕获 **1 个尺寸**，约 2 s、0.07 GiB；
  - 警告 `causal_conv1d_update_npu` 不可用、回退 PyTorch（本服务无 decode，未影响启动）。
- eager 对照：同一命令加 `--enforce-eager`，同 env、同端口，紧接 graph 服务之后启动。

## 2. 结果

30 次正式请求、10 次预热、C1：

| 请求 | 配置 | mean | p50 | p95 | p99 | dec/s |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 307 | graph | 116.31 | 113.90 | 129.37 | 133.57 | 8.594 |
| 307 | **eager** | **109.95** | **106.93** | **123.36** | **128.51** | **9.091** |
| 967 | graph | 168.38 | 168.06 | 170.02 | 172.84 | 5.936 |
| 967 | **eager** | **168.20** | **167.30** | 171.67 | 177.14 | **5.942** |

- 307 token：graph mean **+5.8%**、p50 +6.5%、p95 +4.9%、吞吐 −5.5%，eager 明确更快；
- 967 token：graph mean +0.1%、p50 +0.5%、p95 **−1.0%**、p99 −2.5%，基本持平、方向混杂；
- graph 服务冻结 8 例 **8/8**，协议输出正常。

## 3. 解释

1. **pooling 不能使用 full graph**：vLLM 只允许 PIECEWISE，且 capture size 只有 `[1]`；prefill 仍是 `torch.compile` 的动态图，不能像 decode 那样用固定 shape graph 消掉全部 dispatch。
2. **compile/graph 自身有开销**：307 token 的请求短，graph replay/分段/guard 成本高于省下的 dispatch；969 token 设备占比更高，graph 的收益被设备时间淹没。
3. **CPU dispatch 假设没有被 graph 兑现**：307 eager 每层约 2 ms 的 dispatch 仍在，但 graph 方案没有更快；说明瓶颈还包括 vLLM eager 模型内部的 Python/调度，而不是单纯 CUDA graph 能覆盖的 kernel 序列。
4. **A3 缺少 `causal_conv1d_update_npu`**：回退 PyTorch 会 stall decode-FULL；虽然本服务无 decode，但说明 graph 路径在当前栈上并不完整。

## 4. 采用决定

- **不采用 graph/ACL graph**：可运行、质量正常，但 307 更慢、967 无收益；保持 `--enforce-eager` 的提交配置。
- **不再投入 graph 调优**：pooling 的 full graph 被上游禁用，PIECEWISE + 动态 compile 对短/中请求没有帮助。
- **继续 joint head/pooler CPU 与 schema cache**：这两项是 307 残余里更直接的 host 成本；967 P95 仍以设备侧（MLP/INT8）为主。
- 证据：`Clef-27B/logs/gdn-data-path-20261115/graph-test/`、`eager-test/`、`restore-graph/`。
