### 2.2 最小复现与定位链

1. **HTTP 并发本身不是原因**：在 seqs1 服务上以 C8 重放 16 条差异子集，输出与全量 S1 逐位一致。
2. **同批相同输入得到不同结果**：把同一条请求复制 4 份同时提交到 seqs4 服务；服务日志记录每批的实际长度与末层 hidden 校验和。批内三份相同输入得到不同 hidden；单独执行的那份始终匹配 S1。重复运行后，批内输出是同一组值按批内位置轮换，说明结果依赖**批内位置**而非请求内容。
3. **逐层定位**：在真实模型上记录每层末 token 的 hidden 校验和。`input_layernorm` 输出在三份相同输入间逐位一致；`linear_attn` 输出首先出现差异；其子模块 `in_proj_qkvz` 一致，`in_proj_ba` 在 TP0 上出现 1 个 BF16 ulp（0.015625）差异，随后被后续层放大。
4. **算子和 GEMM 边界**：
   - GDN 融合算子多序列隔离：同一次调用 3/4 条 vs 分序列调用，12 个用例输出与 final state 全部逐位一致（`gdn-kernel-probes.json`）。
   - causal-conv1d 多序列、脏 cache、zero/random initial state：6 个用例逐位一致。
   - 原始 BF16 GEMM 对相同行通常逐位一致；但用真实 `in_proj_ba` 权重离线重放可复现同一 1 ulp 行差，说明这是**权重相关的批内位置数值效应**（累加/分块顺序），不是输入或布局错误。
   - `ATB_MATMUL_SHUFFLE_K_ENABLE=0` 不改变结果；把 `in_proj_ba` 改成 FP32 也不消除（FP32 输出转回 BF16 时仍会跨舍入边界）。
5. **按序列执行 `in_proj_ba`（候选）**：把 48 个 GDN 层的 BA 投影按 prefill 序列切分执行，首层 `linear_attn` 差异被消除，同批三份输出逐位一致；但 16 条差异子集在 C8 仍出现 0.104 的最大概率差（其他 GEMM/层的批内位置效应仍在），**未通过 0.03 门槛，不采用**。
6. **B2 边界**：`max_num_seqs=2`（B2）在同样的 16 条差异子集上 4 条 >0.03，最大 **0.179360**（`b2-subset16-c4.json`）；说明问题不限于 B4，B1 是唯一通过该门槛的合批配置。

### 2.3 根因结论与采用决定

- 根因：固定 Ascend 栈上，跨请求合批使相同输入在不同批内位置进入不同 GEMM tile/累加顺序；BF16 舍入差经 64 层和联合决策头放大，导致近边界样本的概率显著变化。它是**批内位置相关的数值非确定性**，不是模型逻辑、schema 映射、token/span 或缓存错误。
- 在不改动 CANN/AscendC 内核或强制逐请求执行的前提下，seqs4 合批无法满足 0.03/0.05 工程门槛。
- **采用：最终 S2 使用 seqs1（B1）**；seqs4 的 13.764 dec/s 仅保留为吞吐候选，并明确标注质量不通过。未调整门槛（0.03/0.05 保持不变）。

## 3. GDN 候选真实分支覆盖

### 3.1 旧 guard 的真实行为

固定源码 `_split_head_first_conv_output` 通过 `split → transpose → unsqueeze` 产生非连续 `[1,T,H,D]` 视图。旧候选 guard 要求 `q/k/v.is_contiguous()`。真实服务短窗口（8 个冻结请求，`CLEF_GDN_BSND=1`）：

```text
fallback n=1 reason=non-contiguous q=(1,143,8,128) stride=(18304,128,18304,1) contig=(False,False,False)
```

命中 0 次；所有 GDN 层走 baseline 路径。因此第三轮“候选已执行、收益被重叠吸收”的结论不成立，已撤回。

### 3.2 修正后的候选

- guard 仅保留 `dim==4` 与 BF16 dtype；在候选内部先 `q.contiguous()` / `k.contiguous()` 再 `l2norm_fwd`，`v` 同样 contiguate，保证 stable ABI 收到连续输入。
- 保留 baseline 路径与明确支持范围；非 4D/非 BF16 输入仍回退。
- 真实服务（8 请求 × 3 轮）：`input` 记录显示入口仍为非连续，`hit` 计数达到 1000/rank，`fallback=0`；8 个冻结用例在 `/v1/systemone` 与 `/v1/decide` 均逐位一致。
- 多序列 GDN/conv 隔离微基准全部逐位一致；`in_proj_ba` 的批内位置差是另一层问题，与本候选无关。
- **性能口径**：历史 ~3 ms 为 `perf_counter + npu.synchronize` 的 wrapper 同步 wall（含主机下发与设备等待），不是设备独占时间；本轮不声称端到端收益，候选保留为“已验证可运行、默认关闭”的布局选项。

## 6. Schema cache v2 链路

`runtime/apply_schema_cache_patch.py` 已重写：

- 上游 `strategies.py` SHA256 固定为 `d7e25f1d879cd0dc2d8e38629805a66018a9c63e364572d6cbfee6a9fedd97bb`。
- `--check`：识别 `upstream` / `v2` / `v1` / `unknown` 及版本号。

测试：
