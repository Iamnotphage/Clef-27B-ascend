## 5. BF16 权重 NZ 格式 A/B（阶段4）

现场源码核对（固定 vLLM-Ascend `89eb8a5e`）：`ascend_config.py` 默认 `weight_nz_mode=1`；`utils.py::_should_trans_nz` 对 BF16/FP16 仅 mode=2 转换；`ops/linear.py::process_weights_after_loading` 对全部未量化 Linear（除 conv1d、保留 ND 的兼容层）调用 `maybe_trans_nz`。

- **kernel 证据**（profiler 短窗口，fixed307 B1×5，TP2/4096）：mode=2 后 gate_up/down/qkv/GDN 投影全部切换为 `aclnnMatmulWeightNz_MatMulCommon_MatMulV2`（每 rank 1520 调用/5 请求，NZ 布局 `[k/16, n/16, 16, 16]` shape 确认）。
- **同口径设备时间**：matmul 族 46.503 → 42.172 ms/request/rank（**−9.3%**），低于 20% 条件估算；未观察到新增格式回转或 TransData 类开销（转换发生在加载阶段一次完成，加载内存 25.76 GiB 不变，KV 28.47 GiB 不变）。
- **端到端**：mode=2 s4-c8 = 19.166 rps（p50 415.2/p95 420.2），s1-c1 = 8.122 rps（p50 122.5/p95 133.5），相对 mode=1 基线（19.325 / 8.237）**−0.8% / −1.4%**。

结论：**拒绝 weight_nz_mode=2，保留默认 mode 1**。线性层设备时间节省未转化为端到端收益（该算子族与通信等待重叠、且 NZ kernel 在此 shape 下收益有限），属失败候选，配置与证据保留。

## 6. 有界 schema token 缓存（阶段5）

对固定 vLLM `strategies.py::JointSchemaStrategy.encode` 实施 production 缓存（补丁 +111/−9 行，基线 SHA `d7e25f1d…`、补丁文件与回退方式已存档）：

- 仅缓存 schema 片段 tokenize 调用点；键含 tokenizer `name_or_path`/`revision` 与 `add_special_tokens=False` 加完整渲染片段；值存不可变 token tuple；命中返回独立 list；LRU 双预算（默认 4096 条目 / 4,000,000 token）；**state 永不经缓存**（调用点结构保证）；默认关闭，`CLEF_SCHEMA_TOKEN_CACHE=1` 或 additional_config 开启（后者受 pydantic 严格校验限制，实际用环境变量）；每 500 次 encode 输出统计。
- **离线验证**（真实 ServingEncoder 构造 + 真实 tokenizer）：18 个变体（5 用例 + fields-8 × 3 个 state 变体）在缓存关/冷/热/再热下 **ids/schema/orders 逐位一致**；候选重排、增删、指令变更、状态变化、淘汰（tiny budget 8 条目触发 1073 次淘汰）、交叉序列、值修改防护全部通过。
- **CPU A/B**：混合负载 encode 均值 1.262 → 0.119 ms（**−89.6%**；p50 0.436 → 0.095）。
- **API A/B**（env 开启，三轮）：s4-c8 = 19.436/19.375/19.328（均值 19.380，较关缓存 +0.28%，p50 −0.2%）；s1-c1 = 8.164（基线 CV 内持平）。运行时统计：16980 命中 / 20 未命中 / 0 淘汰（每服务实例 20 个唯一片段）。
- **质量门**：协议校验通过；B4 混合并发 771/771 离散一致，概率最大差 0.000851（与关缓存完全同界）。

结论：缓存安全、有正收益且开销可忽略；**保留默认关闭，推荐在 S2 吞吐配置开启**（env 一行），八字段类负载 CPU 收益更大（离线 fields-8 编码 ~5-7ms 量级）。
